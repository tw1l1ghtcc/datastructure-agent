# 《看懂每一步》Alpha 冲刺计划

## 一、前期工作与改进方向

前期已经有二分查找和冒泡排序两个演示，基本打通了「选择算法 → 输入数据 → 运行并回放 → 查看源码、变量与步骤辅导」的流程。这次冲刺要把这套流程扩展到更多数据结构和算法，让队友交付的实现能在同一个工作台里运行。 [分工与任务单 #44](https://github.com/tw1l1ghtcc/datastructure-agent/pull/44) · [任务与验收要求 #47](https://github.com/tw1l1ghtcc/datastructure-agent/pull/47)

| 前期问题 | 冲刺改进方案 |
|---|---|
| 算法实现合入后，有时还缺少工作台入口或回放视图。 | 分别记录「实现已合入」「工作台已接入」「已验收」三种状态。接入后实际检查菜单、输入、运行和回退。 |
| 不同结构的状态差异较大，数组的显示方式难以直接用于图、树和哈希。 | 共用单步、播放和回退控件，按结构联调显示。优先验证图、并查集和树，再推进哈希槽位及桶链。 |
| 只对照最终结果，容易漏掉高亮错行、变量滞后和回退状态不一致。 | 每包先选代表算法走通验收，再批量接入。复审既检查计算结果，也核对每一步的源码高亮、变量和显示状态。 |
| 提交记录、测试结果和展示截图容易分散，临近演示时再找耗时。 | 随交付保存 PR、复现输入、测试结果和短录屏，统一更新冲刺日志，供博客、PPT 和 Vlog 使用。 |

## 二、冲刺目标与交付

1. **扩展算法覆盖。**在原有两个样例基础上，完成 A–G 七个算法包共 **54 项演示**的实现、接入与验收。工作台支持选择算法、自定义有效输入、单步、回退和重置。
2. **保持回放准确。**算法结果、源码高亮、变量和结构状态应对应同一步。输入不合法时，页面应给出清楚的提示。动画和状态表都可用于展示执行过程。
3. **留下可核对的记录。**按包记录提交、问题、复验和接入状态，整理冲刺计划、总结、答辩 PPT 及 3–5 分钟 Vlog。对照计划和实际进度绘制进度曲线或燃尽图。

## 四、14 天推进安排

| 阶段 | 计划工作 | 阶段产出 |
|---|---|---|
| 第 1–3 天 | 确认成员分工、输入格式、步骤数据和试验样例。检查已有工作台入口和播放控件，选定各包代表项。 | 分工表、验收清单、代表算法清单 |
| 第 4–7 天 | 各包先交付代表项；集成成员核对从菜单选择到运行和回退的完整流程，同时吸收复审反馈。 | 代表项 PR、第一批接入与复验记录 |
| 第 8–11 天 | 分批接入其余算法，补齐结构视图和状态表，集中处理输入边界、高亮、回退等问题。 | 可运行的算法入口、问题与修复记录 |
| 第 12–14 天 | 对已接入算法做回归测试，整理仍待接入或待复核的条目，汇总进展和展示素材。 | 验收清单、阶段成果、冲刺总结和演示材料 |

实际提交、合并和接入的日期通过开发日志追踪。进度按「已实现、已接入、已验收」统计，燃尽图以尚未验收的算法数为口径。

## 五、测试与验收

| 检查项 | 怎么验收 |
|---|---|
| 算法结果 | 用正常样例核对输出，再根据算法适用条件补重复值、空输入、非法尺寸、有环或不可达等边界用例。 |
| 页面流程 | 从实际菜单打开，检查自定义输入、运行、单步、回退和重置。异常输入应显示可理解的错误。 |
| 步骤回放 | 至少挑一个关键步骤，对照源码高亮、变量与结构状态。回退后再次前进，确认可以回到同一状态。 |
| 回归与证据 | 运行仓库测试与检查命令，必要时验证展示的 C/C++ 源码能编译和运行。每项确认后记录 PR、用例、检查结果和相应截图或录屏。 |

发现问题时，先在对应 PR 写明输入、出错步骤和预期结果，修复后用同一用例复验。阶段演示优先使用主分支上已接入且复验通过的算法。 [团队项目仓库](https://github.com/tw1l1ghtcc/datastructure-agent)
