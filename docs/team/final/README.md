## 积分与分组

- **1 分**：主要复用已有结构，补算法、步骤和边界测试。
- **2 分**：增加一类执行状态或处理多种边界分支，需要专项联调。
- **3 分**：复杂状态、结构调整或多阶段流程，需要逐步核对和多组测试。
- 算法积分包含步骤输出和样例验证。02 的 18 分单独估算公共动画工作量，01 和 03 按各自里程碑跟踪。各包按首轮实际工作量复估，优先在同类任务内调整。

## 从哪里开始

在[登记表](roster.md)找到自己的任务单。A–G 的任务单逐项列出实现文件和验收要点。对应的 JavaScript 文件已建在 [算法目录](../../../shared/algorithms/final/)，目前为空。每包先填首个代表项的文件，再和 01、02 确认接入方式。通过验收的实现由 01 统一协调接入工作台。

## 每个算法交什么

1. 在个人分支填写任务单链接的实现文件。PR 写清输入、输出、限制和边界行为，并附上与执行逻辑一致的展示代码和稳定行号。
2. 提供可回看的步骤快照。对照[执行状态约定](../../architecture/trace-contract.md)记录当前状态、语义事件、当前代码行和简短说明。算法负责人提供节点、边、数组、指针等结构数据，02 维护渲染和播放。公共协议变更先由 01 与相关成员对齐。
3. 提供至少一个正常和一个边界样例，标出预期结果及关键步骤。首个代表项另交一个人工核对题。
4. 算法负责人先自测，再由 01 安排交叉复核。02 核对画面，01 协调公共入口、验收和合并。PR 附本组改动、复现命令和结果。提交前运行 `npm run check` 与相关测试。

## 三轮交付

| 轮次 | 工作 | 通过标准 |
|---|---|---|
| 第一轮 · 样板 | 01、02 与算法负责人先定接入方式。七个算法包各交一个代表项，02 使用样例轨迹搭视图。 | 代表项能从工作台选中、运行、单步和回看，代码、状态和结果一致。 |
| 第二轮 · 批量 | 同类算法按各自分支并行接入，按视图分批联调。 | 每项有自己的 PR 或可追踪的批次 PR、正常与边界样例、交叉复核。 |
| 第三轮 · 冻结 | 组间交叉复核，01 汇总验收并处理合并和遗留问题，03 准备展示与提交。 | 用实际测试和验收证据更新进度，标出仍待处理的问题。 |
